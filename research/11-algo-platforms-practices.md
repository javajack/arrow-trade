# Algo Trading Product Landscape in India after the SEBI Retail Algo Framework

Research date: 2026-06-12  
Scope: Indian broker API/algo products, third-party algo platforms, implementation patterns, pricing, user sentiment, and a brief global comparison. This is product/compliance research, not legal advice. Items marked **Unverified** are not confirmed from a primary/current source in this pass.

## Executive readout

SEBI's February 2025 framework turned retail API automation from a developer convenience into a broker-supervised regulated workflow. The broker is the principal, API access cannot be open-ended, every API/algo order needs traceable access controls and tagging, and vendor or high-OPS strategies require exchange registration. The clearest exchange implementation source remains NSE's retail algo circular chain: SEBI's original circular on safer retail participation ([SEBI, Feb. 4, 2025](https://www.sebi.gov.in/legal/circulars/feb-2025/safer-participation-of-retail-investors-in-algorithmic-trading_91614.html)), NSE's implementation standards that set the initial threshold at 10 orders per second per exchange/segment and require static IP controls ([NSE/INVG/67858, May 5, 2025](https://nsearchives.nseindia.com/content/circulars/INVG67858.pdf)), and NSE's detailed operational modalities covering generic algo ID 99999, vendor empanelment, product/strategy registration, audit documents, TATs, and re-registration triggers ([NSE/INVG/69255, July 22, 2025](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip)).

The Indian market has split into four product postures:

| Posture | Who is doing it | Product meaning | Compliance meaning | Arrow Trade lesson |
|---|---|---|---|---|
| API-first broker | Zerodha, Dhan, Fyers, Upstox, ICICI Breeze, m.Stock, Shoonya | Broker exposes order/data APIs directly to retail developers. | Static IP, API key, 2FA/OAuth, OPS throttles, order tagging, market-order restrictions and audit trail are broker responsibilities. | Build the API console as a regulated product surface, not a hidden developer page. |
| Compliance-visible broker | Upstox, ICICI Breeze, Dhan | Docs explicitly show retail algo rules: static IP, regular vs registered rates, market order ban, algo ID field or kill switch. | Less ambiguity for users, but more support load when reviews or IP mapping block trading. | Transparent error codes and approval status tracking reduce community anger. |
| No-code/strategy platform | Streak, Tradetron, AlgoTest, Quantman, uTrade Algos, Quantiply | Users build/backtest/forward-test and connect to a broker for live execution. | Under the framework, vendor algos need exchange empanelment/product/strategy registration unless they are only analytics or client-owned low-OPS tooling. | Marketplace and no-code flows need an exchange-registration backend and broker-side hosting/controls. |
| Institutional vendor stack | Symphony Presto, Greeksoft, ODIN, TradeLab | OMS/algo/low-latency vendor infrastructure sold to brokers, prop desks and institutions. | These vendors already live closer to exchange-certified systems, but retail distribution now brings RA, disclosure, suitability and grievance risk. | Institutional tech is not enough; retail UX, disclosures and support are the differentiator. |

## Regulatory product baseline

| Requirement | Practical implementation | Source | Product impact |
|---|---|---|---|
| Broker-as-principal | Broker is responsible for API keys, vendor due diligence, approvals, monitoring, grievances, and audit trail. | [SEBI Feb. 2025 circular](https://www.sebi.gov.in/legal/circulars/feb-2025/safer-participation-of-retail-investors-in-algorithmic-trading_91614.html) | Vendors cannot be treated as independent apps from a compliance standpoint. |
| Static IP | Client/vendor/broker static IP must be mapped; one primary and optional secondary IP; updates normally no more than once per week; same IP generally maps to one client except defined family sharing. | [NSE/INVG/67858](https://nsearchives.nseindia.com/content/circulars/INVG67858.pdf) | Biggest retail friction point; drives VPS/cloud workarounds. |
| Registration-free personal algos | Self-developed client algos within 10 OPS do not require formal strategy registration, but still require API controls and generic tagging. | [NSE detailed modalities](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip) | "No registration" must not be marketed as "no compliance". |
| Registered algos | Client algos above 10 OPS, broker-generated algos, and vendor algos require exchange approval and unique algo IDs. | [SEBI Feb. 2025 circular](https://www.sebi.gov.in/legal/circulars/feb-2025/safer-participation-of-retail-investors-in-algorithmic-trading_91614.html), [NSE modalities](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip) | Need per-strategy forms, approval status, algo ID mapping and change-control. |
| OPS throttles | Initial TOPS is not exceeding 10 orders/sec per exchange/segment for unregistered retail algos; exchanges may revise. | [NSE/INVG/67858](https://nsearchives.nseindia.com/content/circulars/INVG67858.pdf) | Rate limiter must be exchange/segment aware and based on broker-server calendar seconds. |
| Generic algo ID | NSE modalities specify generic algo ID 99999 and NNF 13th digit 0 for unregistered within-10-OPS client algos. | [NSE/INVG/69255](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip) | API order pipeline must support hidden broker-side tagging even when client sends no algo ID. |
| Market orders | NSE retail algo modalities require price protection with limit price; Upstox and ICICI Breeze publicly implemented "market orders not permitted" for API orders. | [NSE/INVG/69255](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip), [Upstox community](https://community.upstox.com/t/important-update-regulatory-changes-for-api-and-algo-trading-are-now-live/14874), [ICICI Breeze docs](https://api.icicidirect.com/breezeapi/documents/index.html) | API users need migration helpers from MARKET/SL-M to protected LIMIT/SL-L style orders. |
| Vendor empanelment | Algo providers must be exchange-empanelled; NSE modalities set T+30 working days from complete application for empanelment. | [NSE/INVG/69255](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip) | New marketplace vendors have a weeks-long compliance path before live distribution. |
| Strategy registration TAT | NSE lists T+10 working days for normal algo registration and T+7 for execution algos. | [NSE/INVG/69255](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip) | Users need a tracker and realistic SLA messaging. |
| Black-box treatment | Black-box providers must be SEBI-registered Research Analysts and maintain detailed research reports per algo. | [SEBI Feb. 2025 circular](https://www.sebi.gov.in/legal/circulars/feb-2025/safer-participation-of-retail-investors-in-algorithmic-trading_91614.html) | Strategy marketplaces cannot sell opaque signals casually. |

## Practical implementation patterns

### Static IP whitelisting

| Pattern | How it works | Brokers/platforms seen | Compliance rationale | User pain | Arrow product implication |
|---|---|---|---|---|---|
| Primary and secondary static IP | Client submits a primary static IP and optional secondary IP; broker maps API key/order channel to those IPs. | NSE standard; ICICI Breeze documents orders only from registered static IP and weekly update limit ([ICICI Breeze](https://api.icicidirect.com/breezeapi/documents/index.html)); Dhan order docs require static IP whitelisting ([Dhan orders](https://dhanhq.co/docs/v2/orders/)); Upstox community says static IP is mandatory for all API orders ([Upstox community](https://community.upstox.com/t/important-update-regulatory-changes-for-api-and-algo-trading-are-now-live/14874)). | Traceability and prevention of open API abuse. | Retail users with home broadband, mobile hotspot, travel or ISP failover lose flexibility. | Provide IP status, last verified timestamp, pending review state, weekly-change timer, and emergency secondary-IP escalation. |
| Single API key for unregistered algos | Multiple API keys allowed generally, but unregistered low-OPS algos must use one predefined key. | ICICI Breeze documents this restriction for unregistered Breeze API users ([ICICI Breeze](https://api.icicidirect.com/breezeapi/documents/index.html)); NSE standards support this pattern. | Prevents OPS/key-splitting circumvention. | Multi-app users cannot casually run separate bots from separate keys. | Enforce per-client consolidated limits, not just per-key limits. |
| Family/shared IP exception | Same static IP usually maps to one client; family sharing needs defined request/validation. | NSE standard; Upstox user reported family of four could not map same static IP across accounts and staff said no workaround pending exchange clarity ([Upstox community](https://community.upstox.com/t/important-update-regulatory-changes-for-api-and-algo-trading-are-now-live/14874)). | Prevent shared infrastructure masking unrelated users. | Households, small offices and training setups break unexpectedly. | Build family-link request flow with PAN/UCC relationship capture and exchange-compliant approval. |
| VPS/cloud workaround | User runs bot on AWS Lightsail, DigitalOcean, etc.; broker whitelists cloud public IP; user can SSH/web into server from anywhere. | Upstox community users specifically mention Lightsail/DigitalOcean as workarounds ([Upstox community](https://community.upstox.com/t/important-update-regulatory-changes-for-api-and-algo-trading-are-now-live/14874)). | Keeps order-origin IP stable while user mobility remains possible. | Adds cloud skill, cost, secrets/security and uptime management burden. | Offer a broker-reviewed "algo cloud" partner/VPS bundle or managed container with secrets vault and kill switch. |

### "Algo trading cloud" and hosted VPS

The market is moving toward hosted execution because static IP and uptime needs make local laptops painful. Tradetron explicitly sells cloud algo trading with dedicated bots and no local software ([Tradetron](https://tradetron.tech/)). uTrade Algos offers broker setup and exchange-approved vendor positioning ([uTrade Algos](https://www.utradealgos.com/)). The compliance-sensitive architecture is no longer "any SaaS can hold client API keys and fire orders"; under NSE modalities, retail algos and vendor algos have to be broker-controlled/registered and the broker must ensure client data and order origination controls are compliant ([NSE/INVG/69255](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip)).

Arrow should treat hosted algo as one of three models:

| Model | Description | Compliance fit | Product risk |
|---|---|---|---|
| Client VPS | Client owns cloud VM and submits static IP. | Fits client self-developed low-OPS path if broker controls keys/rate/tags. | User security mistakes, leaked tokens, poor monitoring. |
| Broker-hosted container | Broker provides an isolated strategy runtime or managed webhook endpoint. | Best fit for broker-as-principal, audit and kill switch. | Engineering/security burden. |
| Empanelled vendor hosted through broker | Vendor strategies run only after exchange empanelment/product/strategy registration and broker due diligence. | Fits vendor framework. | Slow onboarding and marketplace governance. |

### Strategy marketplaces

Strategy marketplaces are the highest-risk surface because they combine automation, performance claims, advisory/signal behavior and retail users. Tradetron still advertises social trading/marketplace and creator/subscriber pricing ([Tradetron](https://tradetron.tech/)). NSE/SEBI rules mean black-box strategies require RA registration and detailed research reports, while the 2022 SEBI return-claim circular remains a live constraint against direct/indirect claims of expected/past algo returns ([NSE/COMP/53555 carrying SEBI Sep. 2, 2022 circular](https://nsearchives.nseindia.com/content/circulars/COMP53555.pdf)).

Practical compliant marketplace treatment:

| Marketplace element | Compliant treatment | Friction |
|---|---|---|
| Public strategy listing | Show logic category, risk controls, instruments, max loss assumptions and RA/white-box status; avoid return rankings/guarantees. | High for growth marketing. |
| Subscriber activation | Broker maps user consent, UCC, static IP/vendor IP, API key and registered algo ID before live orders. | Medium-High. |
| Parameter edits | Define which changes are user risk settings versus logic changes requiring re-registration. | High for iterative quants. |
| Black-box signals | Require RA registration, research report controls and fresh registration on logic change. | High. |

| Broker-linked paper trading | Tradetron advertises free paper trading ([Tradetron](https://tradetron.tech/)). | Safe if no live orders and no misleading performance marketing. | Make paper-to-live delta explicit: slippage, queue position, rejected-leg scenarios. |

### Kill switches and risk controls

| Control | Current examples | Compliance/product value |
|---|---|---|
| Account kill switch | Dhan exposes API kill switch to disable trading for the current day, with a precondition that positions are closed and no pending orders exist ([Dhan Trader's Control](https://dhanhq.co/docs/v2/traders-control/)). | Gives API users a broker-native emergency stop. |
