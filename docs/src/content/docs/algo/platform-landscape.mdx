The market has split into four postures since the framework: **API-first brokers** (Zerodha, Dhan, Fyers, Upstox, m.Stock), **compliance-visible brokers** whose docs spell out the new rules (ICICI Breeze, Upstox, Dhan), **no-code/strategy platforms** racing through empanelment (Tradetron, uTrade Algos, Streak, AlgoTest), and **institutional vendor stacks** (Symphony Presto, Greeksoft, ODIN) that have the exchange-grade tech but not the retail UX.

## Implementation patterns in the wild

### Static IP: the friction economy it created

| Pattern | Reality |
|---|---|
| Primary + secondary IP submission | Universal (NSE-mandated). ICICI documents the weekly change limit explicitly; Dhan enforces at the order-API level |
| **The VPS workaround** | Home broadband is dynamic, so users rent AWS Lightsail/DigitalOcean boxes for the static egress IP and remote into them — community threads openly trade setup guides ([Upstox community](https://community.upstox.com/t/important-update-regulatory-changes-for-api-and-algo-trading-are-now-live/14874)). A ₹300–600/month shadow cost the framework imposed on every retail algo trader |
| Family IP sharing | Formally possible (per SEBI's Dec 2024 family definition) but broken in practice — a four-account family on one IP found no broker workaround pending exchange clarity |
| Single-key rule for unregistered algos | ICICI Breeze enforces it visibly; prevents OPS-splitting across keys; multi-bot hobbyists hate it |

### The emerging "algo cloud"

Hosted execution is becoming the default answer to static IP + uptime + daily-logout pain. Three architectures, with very different compliance fits:

| Model | Compliance fit | Risk |
|---|---|---|
| **Client-owned VPS** (status quo workaround) | Fits the self-developed ≤10-OPS path; broker still controls keys/throttles/tags | Leaked tokens, no monitoring, user security debt |
| **Broker-hosted runtime** (strategy containers / managed webhooks on broker infra) | Strongest fit — NSE *wants* retail algos hosted on broker servers with data not leaving them ([NSE/INVG/69255](https://nsearchives.nseindia.com/content/circulars/INVG69255.zip)) | Engineering and isolation burden on the broker |
| **Empanelled-vendor hosting via broker** | Legal but slow: empanelment + product + strategy registration first | Marketplace governance, weeks-long vendor onboarding |

No Indian broker currently *sells* the middle option. That gap is examined in [Productizing Algo Compliance](/algo/productizing-registration/).

### Strategy marketplaces after the framework

The 2022 return-claims ban ([SEBI via NSE/COMP/53555](https://nsearchives.nseindia.com/content/circulars/COMP53555.pdf)) plus black-box-needs-RA means the old marketplace playbook (leaderboards ranked by returns, opaque "signals") is dead. Compliant marketplaces now look like: logic-category disclosure, risk-control listings, white/black-box status badges, no performance rankings — and a registration backend per strategy. Tradetron's empanelment shows the model survives; its economics now depend on **compliance throughput** (how fast strategies clear registration) rather than bot capacity.

### Risk controls becoming product surface

| Control | Best current example |
|---|---|
| Programmable kill switch | Dhan's API kill switch (disable trading for the day) ([Trader's Control](https://dhanhq.co/docs/v2/traders-control/)) |
| P&L-based auto-exit | Dhan: daily cumulative profit/loss thresholds trigger exit + optional kill switch |
| Market-order ban + MPP defaults | Upstox, ICICI Breeze — bots written for MARKET/SL-M orders all broke on April 1, 2026; migration helpers were left to forum posts |
| Exchange kill by algo ID | Mandated; requires clean algo-ID propagation, which only Dhan visibly exposes in API responses today |

## What users actually said (April 2026 rollout)

The Upstox community thread is the best live record of enforcement day:

- *"Does static IP apply below 10 OPS?"* → Yes, for all API orders — the single most repeated confusion.
- *"Static IP kills cheap cloud and mobility"* → answered by other users with Lightsail/DigitalOcean recipes, not by the broker.
- *"Family of four, one IP, can't map it"* → no workaround, pending exchange clarity.
- *"Status stuck In Review, orders failing"* → deterministic approval states didn't exist.
- MCX API trading suspended mid-rollout with no per-segment readiness display.

Every one of those is a product requirement Arrow gets to design for from scratch — the competitor's support forum is the requirements document.
